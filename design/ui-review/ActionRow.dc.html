PROPOSAL 02
Say why, before the press
The action row already knows which actions can't run. It just waits until you press one to admit it.
Now
~251 A @5C   Slot 10
Seq A  end@16  ^2.4V
▀▄▀▄▀▄▀▄▀▄▀▄
NO DATA
>Read Edit Gen Rec
All four actions look equally available. Edit, Gen and Rec need a bank in memory; Save needs a completed read of this module. Press one and it tells you — which is how “I tried to read but it didn't read” started.
Proposed
~251 A @5C   Slot 10
Seq A  end@16  ^2.4V
▀▄▀▄▀▄▀▄▀▄▀▄
NO DATA - Read first
>Read ·Edit ·Gen ·Rec
A leading dot marks an action that can't run yet, and the state line carries the reason and the remedy in the same breath. Nothing moves, nothing is added — the row is the same 21 characters.
The state line does the work
NO DATA - Read first
Nothing loaded. Says the fix, not just the fact.
LIVE 8s ago wire 9
Matches the module. Age matters — banks go stale.
EDITED* - not saved
Local changes. The module still holds the old values.
Why this one matters beyond the bug
The 251e's own front panel does not repaint when we write to it — confirmed three ways. So this screen is the only honest account of what the module holds. A state line that distinguishes live, edited and nothing loaded is not decoration; it is the only place that truth exists.
