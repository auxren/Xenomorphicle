A leading dot marks an action that cannot run yet. Nothing moves, nothing is added — except that it does not fit. The font is fixed 6×8, so four dots cost 24 px, and the five labels already end at x=124 with 4 px to spare. As drawn this overflows by 20 px. The first version of this artboard hid the problem by omitting Save. Shipping it means shortening a label, dropping to a 2 px gap, or marking availability some other way — and that decision has not been made.
The state line does the work — these are the strings, verbatim
NO DATA - Read first
Nothing loaded. Says the fix, not just the fact.
LIVE 8s ago
Matches the module. Age matters — banks go stale. Clamped to LIVE 9m+ ago so the field can never overflow the row.
EDITED*
Local changes, drawn inverted. The module still holds the old values.
The middle one used to read LIVE 8s ago wire 9, and that killed it. The format's fixed overhead was 17 of the 21 columns, so a three-digit age plus a two-digit slot index pushed the last character off the right edge — turning wire 10 into wire 1, which does not look truncated because it is a perfectly well-formed slot number. On the screen that precedes a thirty-slot rewrite. The header already prints Slot 11 thirty-three pixels above, so the field was a trap in exchange for a duplicate.
Why this one matters beyond the bug
The 251e's own front panel does not repaint when we write to it — confirmed three ways. So this screen is the only honest account of what the module holds. A state line that distinguishes live, edited and nothing loaded is not decoration; it is the only place that truth exists. It now also distinguishes writing, verifying, verified and four flavours of bad — see the write artboards.
