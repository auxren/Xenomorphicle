# Scope App (oscilloscope + FFT) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the Scope app's peak-envelope monitor with a triggered, auto-ranging multi-channel oscilloscope plus FFT view, for the 2 audio ins, 8 CV ins, 4 TR jacks and the existing CV-out/audio-out monitors.

**Architecture:** All decisions live in pure, host-tested modules:
- **sources and groupings** (`ScopeSources`);
- **a decimating min/max ring** (`ScopeRing`, header-only and ISR-safe);
- **timebase and volts tables plus auto-ranging** (`ScopeRange`);
- **period estimate and trigger** (`ScopeTrigger`);
- **FFT and spectrum columns** (`ScopeFft`);
- **settings persistence** (`ScopeSettings`).

A thin target-only `ScopeCapture` feeds the rings from three hot paths:
- the audio `update()`;
- a per-frame hook in `OC::ADC::Scan_DMA()`;
- the app's `Process()` (core ISR), for TR lanes, with pin interrupts timestamping TR edges.

`ScopeApp.h` is rewritten on top of these. Analysis and drawing run at redraw rate, in loop context.

**Tech Stack:** C++17, Teensy 4.1 (IMXRT1062), Teensy Audio Library (int16 `AudioStream`), weegfx 128×64 with the 6×8 font, standalone host tests via `software/test/run-host-tests.sh`, PlatformIO envs `T41`, `T41_audio`, `T41_console`.

**Spec:** `docs/superpowers/specs/2026-10-24-scope-app-design.md` (read it first, including "Calls settled during review").

## Global Constraints

- App identity unchanged: `OC_APP_CLASS(AppScope, TWOCCS("SP"), "Scope", "Scope")`, `-DENABLE_APP_SCOPE`, AUDIO folder.
- Audio paths are gated on `XENO_CODEC_AUDIO` only, never `AUDIO_INTERFACE` or `ARDUINO_TEENSY41`. Without the codec the app still runs with CV/TR sources.
- Hot-path code (audio `update()`, the `Scan_DMA` hook, `Process()`, TR pin ISR) has no FLASHMEM, no allocation and bounded work, and does nothing when the app is suspended (`APP_EVENT_SUSPEND`). The exception is the screensaver trace, if kept.
- Text uses only the firmware 6×8 font: top line 21 columns, everything below is plot. Inversion is used only for the focused field and for jack-number chips.
- Audio-in volts: int16 full scale 32768 = **9300 mV**, labelled **AC**. CV-in volts: calibrated counts (`OC::ADC::calibrated_value` / `InputCal::Value`) × **1200 / 409.6 mV per count**.
- CV-in raw capture rate **37 500 Hz** per channel (300 kHz / 8). Audio **48 000 Hz**. TR lane sampling **16 666 Hz** (`OC_CORE_ISR_FREQ`).
- Acceptance bar (spec, review call 5): on a steady periodic input the trigger point varies **≤ 1 sample** frame to frame. Auto time/volts change **at most once per second**, never alternating between two values. On a morphing input the trigger stays on the same feature unless the period changes by **> 10 %**.
- New logic gets a host suite registered in `software/test/run-host-tests.sh`, and `SAN=1` must pass too.
- Commits are brief, with **no Co-Authored-By / Claude-Session trailers**.

## Review Focus

- **Flat or absent signal** (unpatched jack, DC on an AC input): auto must not divide by zero or hunt. It holds the last range, shows `no trig` in place of the trigger state, and keeps drawing a free-running trace. Tested in Task 3 (`test_flat_input_holds`) and Task 4 (`test_no_period_on_flat`).
- **Clipped or full-scale audio** (Oren's 10 Vpp+ Buchla audio, or the self-oscillating loopback): range clamps at the top volts/div. Period detection still locks on a clipped square. Tested in Task 4 (`test_clipped_square_locks`).
- **Very slow signal on a fast timebase, and the reverse** (a 0.1 Hz LFO at 1 ms/div, an audio tone at 2 s/div): auto timebase must walk to a fitting division within a few seconds without hunting. Tested in Task 3 (`test_autotime_walks_and_settles`).
- **TR edge storm** (an audio-rate clock patched into a TR jack): the pin ISR stays bounded. The edge ring overwrites and edges are rate-limited, at most one stored per 100 µs. Tested in Task 2 (`test_edge_ring_rate_limit`) and on the bench (Task 9).
- **Channel set changed while capturing / suspend → resume:** rings reset and the first frame after a change draws no stale data. Tested in Task 2 (`test_reset_clears`). App flow is checked on the bench in Task 9.

**Files:**

**Interfaces:**
- Produces:
  - `struct ScopeBucket { int16_t lo, hi; };`
  - `class ScopeRing`:

    - `void Reset(uint16_t decim)`: decim ≥ 1, clears everything

    - `void Reset()`
    - `void Note(uint32_t cyc, uint32_t min_gap_cyc)`: drops an edge closer than `min_gap_cyc` to the previous one
    - `uint32_t Count() const`, `uint32_t At(uint32_t n) const`

### Task 4: Period estimate and triggering (the hard part)

**Files:**
- Create: `software/src/ScopeTrigger.h`, `software/src/ScopeTrigger.cpp`
- Test: `software/test/test_scope_trigger.cpp`

**Interfaces:**
- Consumes: plain `float` arrays, oldest first. The app builds them from `ScopeRing` bucket midpoints (Task 8).
- Produces (`namespace ScopeTrigger`):
  - `float EstimatePeriod(const float *x, int n, int min_lag, int max_lag)`: returns the period in samples (sub-sample, by parabolic interpolation), or 0 when none is found.
  - `int LevelTrigger(const float *x, int n, int window, float level, float hyst, bool rising)`: the start index of a `window`-long frame whose first sample is the **latest** qualifying crossing that still leaves `window` samples after it; −1 if there is none.
  - `class AutoTrigger { public: void Reset(); int Find(const float *x, int n, int window); bool Locked() const; float Period() const; };`
- Algorithm (fixed here, because tests alone don't determine it):
  1. **Period.** Use the normalised AMDF or autocorrelation over the latest `min(n, 4·window)` samples. Pick the **first** lag whose score is within 10 % of the best lag in range, so a ring-mod composite locks to its full repeat period, not a sideband. No period when the p-p is < 1 % of full scale or the best score is weak (correlation < 0.5).
  2. **Candidates.** Rising crossings of the mean, with hysteresis 5 % of p-p, positioned so a full `window` follows.
  3. **First lock.** The candidate whose slope at the crossing is steepest within the most recent period.
  4. **Holding lock.** Keep the previous frame (`window` samples). Score each candidate by normalised correlation with that frame, and pick the best. On a ring-mod morph the same feature wins. If the best correlation < 0.3, or the period changed by > 10 %, drop to rule 3.
  5. **No period.** Return the frame ending at the newest sample, untriggered: `Locked()` is false and the display shows `no trig`.

- [ ] **Step 1: Write the failing tests.** Generate signals in the test:
  - **ring mod:** `x[t] = fold(1.8·sin(2πf1 t)) · sin(2πf2 t)` with f1 = 220 Hz, f2 = 770 Hz at 48 kHz (common period 1/110 s);
  - **sine;**
  - **clipped square;**
  - **flat.**

  Tests:
  - `test_period_sine`: 1 kHz at 48 kHz → 48 ± 0.5.
  - `test_period_ringmod_full_repeat`: ≈ 436.4 ± 2 samples (48000/110), **not** a sideband period.
  - `test_clipped_square_locks`: a ±32767 square at 500 Hz → period 96 ± 1, `Locked()`.
  - `test_no_period_on_flat`: constant input → 0, and `Find` returns `n - window` with `!Locked()`.
  - `test_jitter_steady_ringmod`: 50 successive frames, each shifted by a non-integer number of samples of new signal (simulate the ring advancing 1234.56 samples per frame, window 384). The phase of each found start against the true period varies by ≤ 1 sample.
  - `test_morph_stays_on_feature`: fold depth ramps 1.2 → 2.4 over 50 frames. The start index's phase never jumps by more than 1 sample + the change in the feature's own position. Check it as the max |Δphase| between consecutive frames ≤ 0.05·period.
  - `test_period_change_relocks`: f1 jumps 220 → 330 Hz. Within 3 frames `Period()` matches the new value ± 1 %.
  - `test_level_trigger`: a sine with level 0, hyst 0.05, rising → the start sample value ≈ 0 and the next sample is larger. A level above the peak → −1.
