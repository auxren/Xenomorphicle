Everything here is provisional. The Buchla 251e byte format and the Xenomorpher's SysEx framing are both still being designed/reverse-engineered by firmware in parallel -- see the header comments in sequence-codec.js and sysex-transport.js for exactly what's placeholder and why. This applet is built and tested against the Mock transport, which is an in-process model of the firmware's own session FSM (Bus200eBridge.cpp) rather than a stub — a mock read/write travels through the real framing code. Nothing here has been run against real hardware yet: the firmware side (USB MIDI SysEx RX → card image → MasterRestore) is host-tested only, and the 200e bus timing it depends on is still unverified. Add ?transport=webmidi to the URL to preselect WebMIDI. Read/Write need a module address (two hex digits) — the applet never guesses which module on the bus to touch.
Voltage 0–10V per step, quantized to ~78 mV (7-bit placeholder encoding). Gate column toggles whether a step fires its trigger output. Sequence length trims how many steps play before the sequence wraps.
