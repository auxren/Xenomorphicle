The container is decoded; the field semantics mostly aren't. The byte layout here is the one established from a live MasterBackup(0x5C) of a real 251e and cross-validated against an independent factory reference dump — see Buchla_FW/docs/251e-SEQUENCE-FORMAT.md. Geometry (30 × 2104, header + 4 × 522, 50 × 10 + 22) is high-confidence. What the bytes mean is not: stage byte 0 is very likely the stage CV but has no measured scale, bytes 2–3 are a little-endian 16-bit value that reads like a duration, and the header floats, entry bytes 4–9 and the 22-byte block trailer are carried through untouched rather than guessed at. Editing one stage and writing the bank back leaves every other byte exactly as the module reported it. A read pulls the whole bank and a write puts the whole bank back — 63,120 bytes, 1,503 SysEx packets each way — because that is the only unit the module's BACKUP/RESTORE moves. Nothing here has been run against real hardware yet. Add ?transport=webmidi to preselect WebMIDI, ?slot=7 to open on a slot.
Per stage: value = entry byte 0 (raw 0–255, default 0) and time = entry bytes 2–3 (little-endian uint16, default 4). Entry byte 1 and bytes 4–9 are undecoded and preserved. Per slot: two big-endian IEEE-754 header floats (0.0 / 1.0 on an untouched module). Per sequence: block-trailer byte +1, 120 by default.
