Session — not on the panel

Every button, encoder detent and injected event since boot, with the simulated milliseconds between them. Paste it into a message, or save it and replay it with ./build/xeno-sim --replay session.txt — the same session produces the same frames, every time. The frame copies out in the module console's own capture format, so python3 fbdiff.py device.hex sim.hex compares them.

Event log

Writes are discarded. A confirmed Save runs the real guard, the real diff and the real MasterRestore call, then the bytes go nowhere — the log says so, every time.

Chords — holding two controls at once

Several real gestures are chords: the firmware dispatches on the set of buttons held, not on the one that moved. Both ways of holding are shown in the panel's held line.

l+rboth encoder pushes → the 200e preset-bus overlay
a+rA + right encoder → the app menu
a+bA + B → screen flip (in the Setup app)

Keyboard: hold the first key down and tap the second — keys are held for as long as you hold them.
Mouse: a click can only hold one thing, so right-click (or shift-click) a button or knob to latch it down; it stays visibly depressed and outlined until you click it again. Latch encL, then click encR.

Same letters as the terminal build. Mouse wheel over a knob turns it (down = +1); dragging around it turns it; a click pushes it. Holding a button past 500 ms is a long press, which is what STORE in the preset overlay wants. q quits the terminal build and is inert here.
